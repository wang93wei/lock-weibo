## 背景

两个独立问题，一并修：

**问题 A（已诊断，working tree 已改）**：执行阶段对预览快照里 `isPrivate` 的微博重复打"跳过"日志。`lockByIds` 已改为静默跳过（只累加计数），并修正了不实的 doc 注释。这部分**已完成**，本计划不再动。

**问题 B（本计划主体）**：`date` / `before` 筛选当前用 `mymblog` 全量分页 + 客户端过滤，慢且费请求配额。微博有服务端按时间筛选的 `searchProfile` 接口，但实测发现：
- `page` / `max_id` / `since_id` **全部被忽略**，只能靠缩小 `endtime` 推进游标。
- 单页返回 **50 条**（mymblog 是 20）。
- 缺 `referer` 或 `user-agent` 头会 **403**（比 mymblog 严）。
- **能搜出 type=1「仅自己可见」的微博**（实测命中），对锁定场景可用。

## 改动范围（只动预览/数据收集路径，执行路径零改动）

执行（`lockByIds`）只按 mid 锁，与数据源无关 → 不动。

### 1. 修正 research notes（AGENTS.md 硬性要求，不能留错误契约）
`.trellis/tasks/07-27-weibo-batch-locker/research/weibo-api-notes.md` §6 当前写的"page 递增翻页 / list.length===0 终止"基于错误假设，改为：
- `page`/`max_id`/`since_id` 实测全无效（三请求返回逐字节相同 50 条）。
- 分页策略：取本页最旧条 `created_at`（Unix 秒）作下一页 `endtime`，page 恒为 1。
- 单页 50 条；终止 = 本次无新 mid（防同秒碰撞死循环）或 list 为空。
- 必带 `referer` + `user-agent`，否则 403。

### 2. 新增工具函数
- `dateStrToEpochSec(dateStr, endOfDay=false)` — "YYYY-MM-DD" → Unix 秒。`endOfDay=true` 时取 23:59:59（endtime 用，含当天，避免边界丢失）。
- `nowEpochSec()` — `Math.floor(Date.now()/1000)`。

### 3. 新增 API 层 `fetchSearchProfilePage`
仿 `fetchBlogPage` 结构：走全局 `rateLimiter.acquire()`、补 `referer`+`user-agent` 头、403→AUTH / 414·429→RISK / `ok!==1` 分类、返回 `data.data`。参数 `{ uid, starttime, endtime }`（page 恒 1）。

### 4. 新增编排 `runApiModeSearchProfile(opts)`
与 `runApiMode` 同签名（`onLog`/`onProgress`/`signal`/`dryRun`），但：
- 入参多一个 `{ starttime, endtime }`（由 UI 从 filterCfg 算出）。
- 主循环状态：`curEnd = endtime`；每页 fetch 后把命中项 push 进 `stats.hits`（与 runApiMode 一致，含 isPrivate 标记，供执行阶段复用）。
- **去重 + 推进**：维护 `seenMids = new Set()`；本页新 mid 处理，已见的跳过；取本页**最旧条** `created_at` 转 epoch 秒 → 下一页 `curEnd`。
- **终止**：`list.length===0` 或 `本页无任何新 mid`（同秒碰撞兜底）或达 `MAX_PAGES_FALLBACK`。
- isPrivate 跳过、dryRun 命中日志、stats 字段与 `runApiMode` 完全一致（保证 `lockByIds` 无缝复用）。

### 5. UI `doPreview` 按筛选类型分发
- `date` → 算 `starttime=start 00:00:00`、`endtime=end 23:59:59` → `runApiModeSearchProfile`
- `before` → `endtime=now-Nmonths 00:00:00`、`starttime` 省略（实测不带 starttime 可工作；若返回异常降级传早期日期 946684800=2000-01-01）→ `runApiModeSearchProfile`
- `recent` / `mid` → 维持 `runApiMode`（mymblog 全量分页，无服务端替代）

`sameFilterCfg` / `doRun` 的复用校验逻辑不变（hits 结构一致）。
