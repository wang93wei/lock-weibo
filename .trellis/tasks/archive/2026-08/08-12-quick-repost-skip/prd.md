# 修复快转重试并支持可选批量取消

## Goal

批量锁定扫描到快转时不再误调可见性接口；用户可在不改变现有主流程的前提下，主动选择同时取消筛选范围内的快转。默认行为保持只锁定本人微博，所有真实修改均经过预览、分项确认，并可中途停止。

## Background

- 快转条目展示原作者微博，顶层 `user.idstr` 不是当前 UID，并通过 `ori_uid` / `ori_mid` 与“取消快转”菜单表达当前账号的快转关系。
- 对原微博 `mid` 调用 `modifyVisible` 实测返回 HTTP 400：`{"ok":0,"message":"not your own weibo!"}`。
- 2026-08-12 当前微博官方 bundle 实现显示：取消快转走 `POST /ajax/statuses/destroy`，请求 ID 必须是快转记录 `ori_mid`。
- 普通转发的顶层所有者仍是当前账号，并带有 `retweeted_status`；它仍属于可锁定范围。

## Requirements

- 在现有筛选区增加默认关闭的“同时取消筛选范围内的快转”复选项，不增加独立操作模式。
- 关闭复选项时，快转继续作为不可修改项跳过，不发送 `/destroy`；其他行为与现有锁定流程一致。
- 开启复选项时，预览将含有效 `ori_mid` 的快转列为“待取消”；缺少 `ori_mid` 时安全跳过并记录原因。
- 快转无论是否取消，仍计入“最近 N 条”连续时间线目标和“已扫描”。
- 计数区以 3×2 展示成功、跳过、失败、已扫描、待锁、待取消。
- 确认框一次分项显示待锁、待取消和跳过数量，并提示取消快转不会因停止而回滚。
- 执行固定先锁定、后取消快转；两类调用共享全局滑动窗口限速和 AbortSignal。
- 执行成功后更新预览快照，重复点击执行不得再次锁定或取消已完成项目。
- 最终总结分别报告锁定成功、取消成功、跳过和失败数量。
- `modifyVisible` 和 `destroy` 均解析非 2xx 正文；AUTH 终止、RISK 长等待、网络/5xx 指数退避、确定性 4xx/业务拒绝不盲目重试。
- 同步更新一手 API 契约记录以及 userscript/面板版本到 `0.6.9`。

## Acceptance Criteria

- [x] 默认关闭复选项；关闭时快转不进入待取消且 `/destroy` 请求数为 0。
- [x] 开启后，快转使用原微博 `mid` 展示、使用 `ori_mid` 请求 `/ajax/statuses/destroy`。
- [x] 官方菜单判据和所有权字段兜底均能识别快转；普通转发不被误判。
- [x] 缺少 `ori_mid` 的快转计入跳过并显示明确原因。
- [x] 预览显示独立待锁/待取消数量；切换复选项后旧预览不可执行。
- [x] 确认框分项说明两类动作，执行顺序为先锁后取消。
- [x] 停止可中断两阶段执行，已完成操作不回滚；再次执行只处理剩余项目。
- [x] AUTH/RISK/4xx/5xx 与网络错误按需求分类，全部调用共享同一限速器。
- [x] 最终总结分别报告锁定成功与取消成功；版本号两处均为 `0.6.9`。
- [x] `node --check`、Node VM 行为回归和 `git diff --check` 通过。

## Out of Scope

- “仅取消快转”的独立模式。
- 取消普通转发或删除原创微博。
- 对缺少 `ori_mid` 的快转猜测请求 ID。
- 引入构建、测试或 lint 工具；项目仍为单一 userscript。
