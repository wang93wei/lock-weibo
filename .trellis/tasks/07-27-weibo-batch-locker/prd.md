# 微博批量锁脚本

## Goal

提供一个 Tampermonkey 用户脚本，让用户在 weibo.com 登录态下，按多种条件**批量**将自己已发布的微博设为「**仅自己可见**」（可见性 type=1，可恢复），并能在执行前预览、执行中随时停止。

## Requirements

### 功能需求

- **R1 锁定操作**：将选中的微博可见性改为「仅自己可见」（type=1）。
- **R2 筛选方式（单选，共四种）**：
  - R2.1 发布日期范围：`[起始日期, 结束日期]`，按微博 `created_at` 过滤，闭区间。
  - R2.2 时间预设（动态）：选择「1个月前 / 3个月前 / 半年前 / 1年前」，锁定发布时间**早于**（今天 − N个月）的全部微博。截止日在执行时实时计算（动态锁）。严格小于截止日（=当天的不锁）。
  - R2.3 mid 数值范围：`[起始mid, 结束mid]`，按 `mid` 数值大小过滤，闭区间。
  - R2.4 最近 N 条：取按时间倒序的前 N 条。
- **R3 自动跳过**：已是「仅自己可见」(`visible.type === 1`)的微博自动跳过，不重复请求。
- **R4 执行模式**：API 模式，直接调用 `/ajax/statuses/modifyVisible`，速度快、稳定。（点击模式经评估后剔除——DOM 选择器脆弱、维护成本高，且 API 模式已实测可行。）
- **R5 随时停止**：执行过程中可随时点击「停止」立即中断，已完成的不回滚。
- **R6 预览（dry-run）**：默认 dry-run，执行前列出命中清单（mid、发布时间、当前可见性、正文摘要），不发起任何修改请求。
- **R7 二次确认**：从 dry-run 进入真实执行前，需用户二次确认（弹窗显示命中数量）。
- **R8 进度反馈**：实时显示成功 / 跳过 / 失败计数、当前处理中的 mid、滚动日志。
- **R9 限速可配**：每条 `modifyVisible` 之间的请求间隔可配置（默认 ~1.5s 随机），避免风控。
- **R10 翻页限速**：`mymblog` 分页请求之间固定延时（默认 0.8s），避免 dry-run 扫描时连发请求触发微博风控（实测连发 ~12 页会触发"访问频次过快"）。
- **R11 风控自愈**：识别微博限流信号（HTTP 414/429，或响应含"频次/频繁/过快"），自动暂停 30s 后重试，而非直接失败。

### 非功能需求

- **N1 自包含**：单文件 `.user.js`，无外部依赖（不引入 jQuery 等第三方库）。
- **N2 不污染页面**：UI 面板用 Shadow DOM 隔离，避免被微博 CSS 影响，也不影响微博页面。
- **N3 鉴权无感**：复用当前登录态 cookie，用户无需手填 cookie/token。
- **N4 安全护栏**：默认 dry-run；真执行前二次确认；cookie 失效给出明确提示而非静默失败。
- **N5 只在 weibo.com 生效**：`@match https://weibo.com/*`。

## Acceptance Criteria

- [ ] AC1 脚本在 `weibo.com/u/<自身uid>` 页面注入浮动控制面板，不被微博样式破坏。
- [ ] AC2 四种筛选方式（日期范围 / 时间预设 / mid范围 / 最近N条）各能正确筛出预期微博集合（用 dry-run 验证）。时间预设的截止日随当天动态计算，月末日期（29/30/31日）不溢出（如 3月31日 − 1月 = 2月28日）。
- [ ] AC3 API 模式下，对单条微博调用成功后该微博 `visible.type` 变为 1（少量试跑验证，如「最近 3 条」并经用户确认）。
- [ ] AC4 已是仅自己可见的微博在执行时被跳过，不计入成功也不重复请求。
- [ ] AC5 执行中点击「停止」能在一个正在进行的请求/延时周期内停止，不再发起新请求。
- [ ] AC6 dry-run 模式绝不发起 `modifyVisible` 请求。
- [ ] AC7 cookie 失效时给出清晰提示，不静默失败。
- [ ] AC8 `node --check` 语法校验通过；纯函数（筛选器、日期解析、xsrf 解析）单测通过。
- [ ] AC9 （已剔除点击模式，本条作废）

## Out of Scope (MVP)

- 不做批量删除。
- 不做「粉丝可见 / 好友圈可见」的 UI（架构上 `visible` 值可扩展，但本期 UI 只暴露「仅自己可见」）。
- ~~点击模式~~ 已剔除（API 模式够用且更稳；如未来 API 失效可重启该子任务）。
- 不自动刷新/更新登录 cookie（需用户保持登录态）。
- 不做并发请求（串行 + 限速，降低风控风险）。
